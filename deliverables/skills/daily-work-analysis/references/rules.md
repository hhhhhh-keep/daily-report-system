# 日报分析管理口径

## 填报与出勤

- 时区固定为 `Asia/Shanghai`。
- 17:30提交以不可变的首次提交时间 `first_submitted_at` 判定；22:00优先采用通过一致性校验的最终统计快照。
- 两个截止点的“已填写人数”与“应填写人数”必须使用同一资格人群：全天请假人员即使存在日报记录，也不得计入截止点已填写人数。
- 统计快照出现已填大于应填、比例超过100%、快照应填与当日确定性口径不一致或比例算术不一致时，禁止直接采用，必须按资格人群重新计算并标注为异常快照重算。
- 全天请假：应工作时段为0，不要求填写任务，不计入未填。
- 半天请假：应工作时段为1，只检查另一个时段；请假时段不得算未填或工作不饱满。
- 只有“请假”而无上午、下午、全天或起止时间时，列为待核验，不自行猜测。
- 请假状态与工作记录冲突时列为待核验，不覆盖任何一方。
- 培训属于已提交日报中的工作类型，不等同请假或未填。

## 人员效能

- 确定性部分统计事项数、完成数、进行中数、阻塞数、项目数和证据覆盖；事项数量不能直接解释为绩效高低。
- AI人员效能观察必须落实到“姓名、具体项目或专项、主要动作、明确产出、主导或协同关系、需关注问题”，不得只输出“工作有序”“事项较多”“整体均衡”等泛化判断。
- 每条人员效能观察至少填写一个真实 `person_id`，并引用该人员对应的 `evidence_ids`；涉及项目时同时填写真实 `project_id`。
- 优先选择存在明确产出、明确阻塞、多人协同、一人承担多个项目或连续推进特征的人员，说明具体事实及管理含义；不得仅按事项数量排序后逐人复述数字。
- 请假人员与全天出勤人员不得只按绝对事项数横向比较，不输出主观绩效评分、优秀/落后排名或无证据的工作饱满度判断。

## 项目与协同

- 正式项目以项目维护主数据为准，日报只提供当天动态和参与证据。
- 主导与协同必须来自任务关系，不根据动作措辞猜测。
- 日报中的项目候选若未关联正式项目，单列为“日报识别待关联项目”，不得强行归并。
- `暂无正式项目`、`内部专项`属于系统占位分类，不作为项目连续性、项目关联性或风险结论中的项目名称输出。
- 正式项目在分析日之前连续超过3个工作日无日报动态时进入关注清单；恰好3个工作日不触发。
- 停滞天数依据工作日历计算，不按自然日计算。

## 证据和模型边界

- 每项语义结论必须引用事实包已有的 `evidence_ids`。
- 模型不得计算或改写人数、率、任务数、停滞工作日数。
- 原文只证明“提交验收材料”时，不得推断“已验收”；只证明“沟通方案”时，不得推断项目已进入交付。
- 模型不可用或校验失败时，输出确定性事实并明确语义分析未采用，不得输出空白章节或占位内容。
- 模型输出固定为 `daily-analysis/1.2.0`：整体判断、人员效能观察、项目连续性、项目关联性及协同、风险事项和次日行动；每个对象统一携带 `summary`、`person_ids`、`project_id`、`evidence_ids`、`limitation_note`。
- 对应确定性事实非空时，项目连续性、关联性和风险章节至少生成一项；不得以“事实包不完整”“无法生成整体判断”等错误占位文本替代分析。
- 引用事后重建项目状态时，`limitation_note` 必须明确说明其时点限制；没有限制说明的结论一律不采用。

## 领导报告固定内容

1. 整体判断；
2. 填报与出勤（实名）；
3. 人员效能观察；
4. 项目连续性分析；
5. 项目关联性及协同分析；
6. 风险评估（含超期无动态关注）；
7. 次工作日管理关注。

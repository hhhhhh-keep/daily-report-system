# Skill 试运行进行中反馈设计

## 背景

Skills 中心的“试运行所选版本”会同步等待规则分析、证据校验和 Word 报告生成。当前页面只在请求结束后显示结果；模型调用耗时较长时，用户看不到处理中状态，容易误认为点击没有生效，并可能重复提交。

## 目标

- 点击试运行后立即提供可见反馈。
- 试运行期间阻止重复提交。
- 请求结束后继续展示已有的成功、降级或失败结果。
- 保持当前页面布局和同步 API，不新增后端任务查询接口。

## 交互设计

页面增加本地 `trialRunning` 状态：

1. 用户点击“试运行所选版本”后，立即将状态设为运行中，并显示“正在试运行，请稍候…”。
2. 运行期间按钮文字显示“正在试运行…”，按钮禁用。
3. API 返回后，沿用现有规则显示成功、降级或失败提示。
4. 无论请求成功还是抛出异常，都在结束时解除运行状态，允许再次试运行。
5. “成对发布”仍按现有成功试运行条件控制，不因本地运行状态改变发布规则。

不显示虚假的百分比或阶段进度，因为现有同步接口没有可靠的进度数据。

## 错误处理

- API 返回业务失败：显示后端的 `errorSummary`。
- 网络或接口异常：显示现有 `apiError` 转换后的错误信息。
- 所有路径都通过 `finally` 恢复按钮状态，避免按钮永久禁用。

## 测试标准

- 使用未完成的 Promise 模拟长时间请求，断言点击后立即显示进行中提示。
- 断言运行期间按钮禁用且文字为“正在试运行…”。
- Promise 完成后，断言按钮恢复，页面显示真实成功或失败结果。
- 现有 Skills 页面测试和生产构建全部通过。

# 日报分析与 Word 模板 Skill v1.2 设计

## 目标

以 `行一二部工作日报_2026-07-31` 领导审阅版为金标准，升级规则分析 Skill 与 Word 模板 Skill，使日报工具在受控 Python 运行时内稳定生成相同信息密度、证据约束和版式质量的报告。改造保持单体架构、无网络权限、Skill 不直接访问数据库。

## 已确认现状

- 系统已有人员、日报、任务、主导/协同、项目主数据、项目衍生状态、项目状态快照、17:30/最终填报快照和工作日历。
- `AnalysisSourceSnapshotService` 已查询上述数据，但 `DailyDataPackageAssembler` 只把周期内任务映射为 `projects.json`，忽略 `projectStates`、`statistics` 和完整工作日信息。
- 因此，当天无任务的在管项目不会进入 Skill，现有 Skill 无法可靠生成长期无动态预警；这不是模型能力问题，而是输入契约缺口。

## 方案

采用“兼容数据包 1.1 + 规则 Skill 1.2 + 模板 Skill 1.2 + 最小宿主映射”的方案。

### 数据包 1.1

保留 1.0 的八个文件与字段，新增三个可选文件。1.2 Skill 同时接受 1.0 和 1.1；读取 1.0 时输出明确的数据覆盖限制，不伪造缺失结论。

1. `statistics.json`
   - 快照类型、统计日期、采集时间；
   - 应填、已填、未填、填报率；
   - 已填、未填、迟交实名名单；
   - 支持 17:30 与最终快照独立展示。
2. `project-status.json`
   - 项目 ID、名称、正式属性、启用状态、业务状态、优先级、负责人；
   - 衍生状态、生命周期、当前阶段、状态开始日期；
   - 参与人数、累计阻塞任务数、最近日报动态日期；
   - 状态基准日、快照采集时间、`captured/reconstructed` 来源标识。
3. `workdays.json`
   - 日期、是否工作日、来源和说明；
   - 覆盖项目最近动态至报告日所需的回溯窗口。

清单仍以 SHA-256 校验每个实际包含的文件。默认无动态阈值为 `3` 个工作日，允许宿主运行参数覆盖；阈值和最终采用值写入事实包。

### 规则分析 Skill 1.2

规则 Skill 只生成确定性事实和有证据的语义分析，不生成 Word。

确定性事实新增：

- 填报驾驶舱：应填人数、17:30已填/填写率、最终已填/填写率、请假人数、未填人数；
- 实名出勤：未填、全天请假、半天请假、待核验；
- 人员效能：任务总数、完成/推进/阻塞分布、工作类型分布、完成与阻塞人员名单；该内容不得解释为个人绩效；
- 正式项目动态：项目状态/阶段/负责人、当日人员、主导/协同、当日任务状态；
- 待关联项目动态：文本识别名称、涉及人员、状态分布、关联提示；
- 长期无动态预警：最近动态日期、截至报告日的无动态工作日数、当前状态、负责人和阻塞数；仅当 `inactive_workdays > threshold` 时进入预警；
- 数据质量：历史快照是否实时留存或重建、缺失字段及受限结论。

模型只消费只读事实包，输出总体判断、人员效能洞察、项目管理洞察、风险和下一工作日行动。每项必须引用已有 `evidence_ids`；人数、比率、名单、日期间隔和状态不得由模型计算或覆盖。模型输出失败时，规则 Skill 仍返回完整确定性事实。

### Word 模板 Skill 1.2

模板 Skill 只消费已验证事实与可选的已验证模型分析，不重新计算业务数字。

固定结构：

1. 标题：`行一二部工作日报`，不含“领导版”；
2. 2×4 深蓝驾驶舱：小号标签、突出数值、统一字体和垂直间距；
3. 总体判断；
4. 填报及出勤；
5. 人员效能分析；
6. 当日项目动态与项目主数据状态：已关联正式项目、日报识别但待关联项目、超过阈值无动态项目；
7. 下一工作日管理关注；
8. 数据口径说明。

除驾驶舱外使用简洁公文格式。主标题、一级标题、正文和表格字体、字号、段距、行距、页边距均由模板资产固定。报告优先控制为两页；表格允许跨页但标题行重复。无数据时展示简洁的“无”或覆盖限制，不重复生成“待人工补充”占位段落。

### 宿主适配

仅修改分析源快照和数据包组装映射：

- 导出已有填报统计快照；
- 导出全部在管项目状态，而不是只导出当日有任务项目；
- 导出回溯工作日；
- 传入可配置无动态阈值；
- 不授予 Skill 数据库或网络权限。

## 错误与降级

- 1.0 数据包：保留出勤、任务和可得项目分析；项目主数据或无动态结论标注“数据包未提供”，不编造。
- 缺少17:30或最终快照：使用可验证提交时间计算时必须标记为重算；无法计算则显示不可用。
- 历史项目快照为重建：报告必须显示重建日期与限制。
- 模型不可用或证据校验失败：输出完整 facts-only 报告，语义段落由确定性管理提示替代。
- 任一未知人员、项目或证据 ID：拒绝模型结果，不进入 Word。

## 测试与验收

采用失败用例先行，分别验证两个 Skill 后再进行成对端到端测试。

### 规则 Skill

- 数据包 1.0 兼容；
- 1.1 新文件完整性、路径穿越、未知版本和交叉引用校验；
- 全天/半天请假、未填和17:30/最终填报口径；
- 人员效能状态分布和实名名单；
- 正式项目人员与主导/协同；
- 当天无任务项目仍进入状态集合；
- `3` 天不预警、`4` 天预警；工作日历排除周末/节假日；
- captured 与 reconstructed 快照说明；
- 模型引用未知证据时拒绝并降级。

### 模板 Skill

- 固定章节顺序、标题、驾驶舱八项指标和实名名单；
- 项目三类表格及下一工作日管理关注；
- 字体、字号、颜色、页边距、表格宽度和重复标题行的 OOXML 审计；
- 禁止“未调用模型或模型结果未通过校验，待人工补充”等重复占位内容；
- facts-only 与模型增强两种路径都能生成可打开的 DOCX。

### 金标准端到端

使用 2026-07-31 数据夹具验证：

- 驾驶舱为应填90、17:30已填88、最终已填88、请假5、未填2、任务115、完成11、阻塞12；
- 未填与请假人员实名；
- 四个正式关联项目包含状态、阶段、负责人和当日人员；
- 待关联项目与人员可追溯；
- 两个项目分别形成5个、4个工作日无动态预警；
- 历史项目状态重建说明存在；
- 输出结构和模板资产与确认版一致。

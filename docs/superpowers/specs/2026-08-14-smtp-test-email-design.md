# SMTP 测试邮件设计

## 目标

管理员在“技术连接”页面保存 SMTP 配置后，可以独立发送一封测试邮件，确认服务器、端口、账号、授权码、发件人、收件人及抄送配置能够完成真实投递。

该测试不依赖 AI 模型、分析 Skill、分析任务、报告生成或定时调度。

## 范围

- 在现有技术连接页面增加“发送测试邮件”按钮。
- 增加管理员专用测试接口。
- 后端读取已经保存并立即生效的分析配置，将数据库字段与服务器环境变量按现有 `SmtpSettings` 规则合并。
- 向当前配置的收件人和抄送人发送一封固定内容的测试邮件。
- 页面显示成功信息，失败时显示可操作但不泄露密码、授权码或内部堆栈的错误信息。

不修改正式分析、Skill、报告生成、定时任务或正式邮件幂等逻辑；测试邮件不写入正式 `analysis_runs` 和 `email_deliveries` 记录。

## 接口设计

`POST /api/admin/configuration/email/test`

请求体为空。接口只接受已登录管理员调用。

成功响应：

```json
{
  "sent": true,
  "message": "测试邮件已发送，请检查收件箱和垃圾邮件目录。"
}
```

配置缺失或投递失败时返回现有统一错误结构。错误信息可以指出 SMTP 未配置、收件人未配置或发送失败，但不得包含密码、授权码、模型密钥和完整异常堆栈。

## 邮件内容

- 主题：`日报分析系统 SMTP 测试邮件`
- 正文：说明这是一封由日报分析系统管理员主动触发的测试邮件，并包含发送时间。
- 附件：无。

## 后端结构

- 新增独立测试服务，复用 `AnalysisConfigurationService`、`SmtpSettings` 和 `EmailGateway`。
- 服务先校验邮件已启用、收件人非空、SMTP 主机和发件人可用，再调用现有 SMTP 网关。
- 控制器只负责权限边界和响应转换，不参与 SMTP 组装。

## 前端交互

- 按钮放在“SMTP 发件箱”区域，与保存配置操作分开。
- 管理员必须先保存配置；按钮调用后端当前已保存配置，不直接传输页面中的密码。
- 发送期间按钮禁用并显示“发送中…”。
- 成功显示绿色状态；失败显示统一错误信息。

## 测试与验收

- 后端测试验证：正确组装收件人、抄送人和 SMTP 设置并调用网关；配置缺失时拒绝发送；异常信息不泄露密钥。
- 前端测试验证：点击按钮调用专用接口；发送期间禁用；成功和失败状态可见。
- 生产构建、后端 Checkstyle 和相关测试全部通过。
- Docker 重建后，在本地技术连接页面实际发送一封测试邮件；任务成功以接口返回和页面状态为准，最终收件确认由管理员在邮箱中核对。

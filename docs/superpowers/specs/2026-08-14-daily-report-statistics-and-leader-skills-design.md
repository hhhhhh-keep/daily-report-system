# 日报统计与领导版 Skill 升级设计

## 目标

在不新增累计统计表的前提下，补齐日报首次提交/最后修改时间展示，提供按自然周、自然月的人员累计填报统计，并将同一确定性口径输入日报分析规则 Skill 与 Word 模板 Skill，使成对试运行能够稳定产出当前确认的领导版日报质量。

## 已确认口径

- 业务时区固定为 `Asia/Shanghai`。
- 17:30 前填写只按不可变的首次提交时间判定；后续修改不改变早填结果。
- 最后修改时间来自日报 `updated_at`。
- 周期为自然周（周一至周日）或自然月，只统计工作日历中的工作日。
- 全天请假计 1 次、1 天；上午或下午请假计 1 次、0.5 天。
- 请假日报属于已填写，不计入未填；培训日报属于已填写并累计培训次数。
- 未填按“人员在该工作日应填且不存在已提交日报”计算。优先采用当日最终统计快照冻结的应填名单；快照缺失时回退到当前启用人员，并在响应中标明覆盖口径。
- 人员效能只描述工作事项、状态、协同和阻塞证据，不作为绩效排名。
- 项目超过 3 个工作日没有日报动态时进入关注清单；只按工作日计算。

## 架构

### 日报管理

保留 `daily_reports.submitted_at` 作为首次提交时间，保留审计基类的 `updated_at` 作为最后修改时间，不新增迁移。新增只读周期统计服务与接口：

`GET /api/admin/reports/period-statistics?period=WEEKLY|MONTHLY&anchor=YYYY-MM-DD`

响应包含周期起止日期、工作日数、统计覆盖口径、部门合计和逐人明细。逐人明细固定包含：应填次数、17:30前填写次数/比例、未填次数、请假次数、请假折算天数、培训次数。

日报列表和详情同时展示首次提交时间与最后修改时间。页面增加“周统计 / 月统计”区域，周期锚点与当前筛选日期共用。

### 规则 Skill

规则 Skill 继续只生成事实与经证据校验的语义结论，不负责 Word。宿主数据包补齐：

- `reports.json.final_submitted_at` 使用真实 `updated_at`；
- `projects.json` 携带正式项目标识、维护状态、阶段、负责人、最近日报日期、参与人数、阻塞数和状态快照日期；
- 事实包新增确定性填报驾驶舱、人员效能、正式项目动态、待关联项目、超过3个工作日无动态项目五组结构化数据。

模型仍只能补充四个语义区块，并且每条结论必须引用事实包中的证据 ID。人数、比例、名单、工作日差值和项目状态均由脚本计算，模型不得覆盖。

### 模板 Skill

模板 Skill 只消费通过 Schema 的事实包和可选分析结果。固定生成：

1. 无“领导版”字样的主标题；
2. 深蓝驾驶舱，小标签、突出数值；
3. 总体判断；
4. 填报及出勤实名统计；
5. 人员效能分析；
6. 已关联正式项目、待关联项目、超过3个工作日无动态项目；
7. 下一工作日管理关注；
8. 数据口径与快照重建说明。

AI 不可用时仍输出完整确定性章节，只把真正依赖语义生成的句子标记为待人工补充，不能退化成只有“基础报告”提示的空壳。

## 兼容与版本

- 两个 Skill 版本升至 `1.2.0`。
- 保留现有 `daily-data-package/1.0.0` 文件集合，新字段采用向后兼容扩展；缺少项目状态时输出“项目状态数据缺失”，不编造。
- 事实与分析 Schema 同步复制到规则 Skill 和模板 Skill，测试校验两份内容一致。
- ZIP 继续使用受控 Python 运行档案、无网络权限、固定入口点。

## 测试与验收

- 后端：周期边界、17:30、修改不影响早填、未填、全天/半天请假、培训、快照回退。
- 前端：时间列、周/月切换、统计字段和空状态。
- 规则 Skill：领导版事实结构、项目状态映射、3工作日阈值、实名名单、证据引用。
- 模板 Skill：标题、驾驶舱、章节、字体、表格、AI缺失降级、DOCX审计。
- 端到端：用 2026-07-31 数据包生成 Word，并与确认版的关键内容清单逐项比对。

## 非目标

- 不建立统计累计表或新的定时任务。
- 不改变日报锁定规则、项目状态推导架构和周/月分析主流程。
- 不把人员事项数量直接换算为绩效分数。

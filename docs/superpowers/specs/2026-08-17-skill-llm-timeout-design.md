# Skill 模型调用超时配置设计

## 目标

让成对 Skill 试运行可为较长的模型响应提供足够等待时间，避免固定 180 秒导致的 `HttpTimeoutException`。

## 方案

后端新增 `daily.llm.skill-request-timeout` 配置属性，ISO-8601 时长格式，默认 `PT300S`（300 秒）。`LlmAnalysisAdapter.analyzeSkill` 使用该属性创建 HTTP 请求；普通日报分析仍保留既有的 90 秒上限。

前端成对 Skill 试运行请求的 Axios 覆盖超时从 240 秒调整为 360 秒。该缓冲时间覆盖后端 300 秒上限及响应回传、数据库保存和网络延迟。

## 边界与错误处理

- 仅影响 Skill 试运行和 Skill 执行的模型调用。
- 不改变请求负载、认证头、模型适配参数或当前失败提示。
- 上游模型仍在配置时限内无响应时，保留现有失败结果；用户可从错误摘要获知失败。

## 验证

- 后端单测断言默认配置为 300 秒，并验证配置值传入 Skill HTTP 请求。
- 前端 API 单测或源码断言确认试运行请求使用 360 秒。
- 执行后端测试、前端 lint 和生产构建。

# AI 分析手动运行超时与状态反馈设计

## 背景

AI 分析中心的“运行分析”调用复用全局 15 秒 HTTP 超时。日报 Skill、模型分析、报告生成和邮件发送通常超过 15 秒，导致浏览器先断开请求并显示“暂时无法连接服务器”，但后端仍会继续执行。管理员可能因此重复点击并创建重复运行。

## 已确认方案

采用最小范围修复：仅为手动运行分析请求设置 240 秒超时，不修改其他接口的全局超时，也不调整后端分析、报告或邮件流程。

运行期间按钮保持禁用并显示“分析中…”，同时展示“AI 分析中，预计需要 1～3 分钟，请勿重复提交”。请求完成后，根据返回的运行记录明确展示运行状态、AI 状态和邮件状态；请求真正失败时才显示接口返回的错误。

## 数据流

1. 管理员选择周期和结束日期并点击“运行分析”。
2. 前端以 240 秒专用超时调用 `POST /api/admin/runs`。
3. 后端同步执行已发布 Skill、模型分析、报告生成和按配置发送邮件。
4. 前端等待响应期间禁止重复提交。
5. 返回后刷新分析结论，并显示运行、AI、邮件三项结果。

## 边界与异常处理

- 不修改全局 Axios 15 秒超时。
- 不新增异步任务、轮询、队列或基础设施。
- 不改变同一分析日期成功邮件的防重复投递规则。
- 240 秒内后端返回 `partial-failure` 时，前端必须显示真实状态，不把它包装成网络错误。
- 超过 240 秒或确实无法连接时，保留统一错误信息；管理员可到“任务记录”核对后台状态。

## 测试

- API 单元测试断言 `runNow` 使用 240 秒专用超时。
- 页面测试断言运行期间按钮禁用、显示预计耗时提示。
- 页面测试断言成功返回后展示运行、AI、邮件状态并刷新结论。
- 前端测试、生产构建通过后部署。
- 端到端选择历史日报运行一次，确认页面不再在 15 秒时报错，并核对数据库运行与邮件状态。

# 功能规格：日报 AI 分析系统

**功能分支**：`001-daily-report-ai-system`
**创建日期**：2026-08-10
**状态**：草稿
**输入**：由 `docs/design-revision-v2.md`（权威来源）和 `docs/system-design.md` 汇总。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 提交并更新今日日报（优先级：P1）

员工无需登录即可打开部门固定日报链接，选择姓名和出勤状态，为当天创建任意数量的工作任务。当日再次打开日报时，可以更新这一份有效日报。

**优先级原因**：结构化的每日任务数据是所有管理和分析用例的基础。

**独立测试**：选择员工与日期，新增多条任务并保存；重新打开后更新一条任务，确认该员工和日期仍只有一份日报。

**验收场景**：

1. **假如**存在在岗员工和当天日期，**当**员工保存含多条任务的日报，**那么**可获得一份日报及其任务明细。
2. **假如**当天日报已存在，**当**员工编辑日报，**那么**更新当前日报而非创建重复日报。

---

### 用户故事 2 - 管理日报和基础数据（优先级：P2）

唯一管理员登录后管理人员、项目、日报/任务记录、业务字典和配置。项目包含可选择的非正式工作选项，以覆盖没有正式项目编码的工作。

**优先级原因**：准确的人员、项目和任务上下文使日报可用于管理。

**独立测试**：管理员维护一名 Employee 和一个 Project，确认它们可在日报中选择并在管理界面查看。

### 用户故事 3 - 分析并分发管理洞察（优先级：P3）

管理员配置分析规则、Prompt、执行时间、分析维度和邮件收件人。定时处理计算客观指标、执行语义分析、创建管理报告、发送邮件，并记录可重试的运行结果。

**优先级原因**：分析将日报转化为人员、项目和资源管理洞察。

**独立测试**：对样例日报运行已配置的分析，验证驾驶舱/报告包含所选维度，且可以查看或重新运行该次结果。

### 边界情况

- 日报没有任务、任务不完整，或出勤状态/日期组合无效。
- 同一员工和日期重复保存时更新当日日报，而非创建第二份。
- 任务引用非正式项目选项，或具有风险/阻塞状态。
- 分析、报告生成或邮件发送失败；失败被记录且可手动重新运行。

## 需求 *(必填)*

### 功能需求

- **FR-001**：系统必须提供一个响应式 `daily-web` 体验，包含员工日报、日报更新和管理员路由。
- **FR-002**：员工必须能够在没有员工账号的情况下提交并修改仅限当天的日报。
- **FR-003**：系统必须为每名员工和报告日期准确保留一份有效日报。
- **FR-004**：日报必须支持任意数量的任务明细，包含时段、项目、工作类型、参与角色、进展/结果、当前状态，以及条件性的事项/协同/风险信息。
- **FR-005**：管理员必须管理 Employee 和 Project 基础数据，包括非正式项目选项。
- **FR-006**：系统必须提供一个管理员账号，支持密码登录、密码哈希、会话或令牌访问、修改密码和退出；不得增加员工账号、RBAC、SSO 或 OAuth。
- **FR-007**：系统必须直接根据已存数据计算日报完整性、任务、项目、时段、异常任务、连续支撑、等待反馈、多人员和多项目指标。
- **FR-008**：AI 分析必须提供人员效能、工作饱和度、项目进展、项目风险、资源协同、资源调配建议和日报质量洞察。AI 仅提供建议，不得执行人员调配或项目决策。
- **FR-009**：确定性的程序规则和 LLM 语义分析必须保持分离。
- **FR-010**：管理员必须无需改代码即可配置业务字典、AI 规则、Prompt 版本、分析维度、计划、邮件收件人、邮件/报告模板和 AI 模型设置。
- **FR-011**：应用必须在内部运行定时分析、报告生成、邮件发送、运行记录、错误查看和手动重跑；n8n 和外部工作流编排不在范围内。
- **FR-012**：方案必须保持使用 Vue 3、Spring Boot、PostgreSQL 和 Docker 的模块化单体。
- **FR-013**：本功能不得引入审批、CRM、绩效管理、工时、多角色、微服务、消息队列、Kubernetes 或复杂审计/安全系统。

### 关键实体 *(功能涉及数据时必须包含)*

- **Employee**：包含姓名、小组、岗位/类型和在岗状态的人员基础数据。
- **Project**：包含客户、行业、阶段、负责人、优先级、状态和可选编码的项目基础数据。
- **DailyReport**：某个 Employee 某日的日报，包含出勤、提交/更新时间和状态。
- **DailyTask**：归属一份日报的任务，包含工作、进展、状态、事项和协同上下文。
- **分析配置与运行**：已配置的规则/Prompt/计划/维度/收件人设置，以及产生的分析、报告、邮件和重试结果。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**：员工无需员工登录即可在一次访问中创建或更新今天的多任务日报。
- **SC-002**：每个员工/日期查询最多返回一份有效日报。
- **SC-003**：一次已配置的定时运行产生所选分析维度、报告和可见结果记录。
- **SC-004**：管理员无需改代码即可更改分析规则、Prompt、执行时间、维度和收件人。

## 假设

- 固定日报链接是已接受的部门内部访问取舍；所选身份不作为作者身份的证明。
- 第一版只有一个管理员，不包含审批或历史日报版本。
- SMTP 凭据由环境管理，不以明文业务数据形式保存。
